## Blocking policy (explicit)

| Situation | Outcome |
|---|---|
| guard exit 0 | allow |
| guard exit 2 (dangerous / protected) | block, reason = script stderr (≤1500 chars) |
| guard crash (other exit), spawn error, 15 s timeout, abort signal | block (fail closed), bounded reason |
| write/edit with missing/empty/non-string `path`; bash with non-string `command` | block as malformed |
| read/grep/find/ls/other tools | not guarded |
| post-write sync failure, nudge/catch-up failure | tool result kept; sync failures append a bounded `[Memory Bank] plan-sync failed` note |

## Deviations

- Plan-sync is called directly (the Codex pattern), not through `hooks/mb-plan-sync-post-write.sh` (broken argv, see above). Edits trigger it as well as writes; `plans/done/*.md` does not, because syncing it would re-list an archived plan as active.
- The protected guard runs in forced `deny` mode. Pi has no PreToolUse "ask" protocol; `MB_ALLOW_PROTECTED=1` stays the script's bypass.
- The EARS pre-write validator (`mb-ears-pre-write.sh`) is not wired. It is a content validator, not a safety guard, and is outside this stage's contract.

## Risks / follow-ups

- Shared hook bug (not fixed, portable `hooks/*` frozen for this stage): `hooks/mb-plan-sync-post-write.sh` runs `mb-plan-sync.sh` with no plan argument, so Claude/Cursor plan-sync after Write never syncs.
- Bash protected checks depend on the portable regex parser. Absolute redirect targets in a project without `.git` are not matched. Interpreter-level writes and custom/extension tools are uncovered. This is not a sandbox, and the reference says so.
- Each `bash`/`write`/`edit` now costs one bank walk-up plus 1–2 guard spawns (each bounded at 15 s). A broken skill install (missing guard script) blocks every mutating call, by the fail-closed design.
- If the graph extension is installed both project-locally and globally, the guards and plan-sync run twice. Both are idempotent, but it costs twice the time.
- With a registered global bank found from a subfolder, the graph/hooks project root is still `ctx.cwd` (no root marker to walk to). Commands run their scripts with cwd = the subfolder; the bank argument is explicit.
