## 2. Bugs found live and fixed test-first

RED logs: `stage5-live/red-live-regressions.log`, `stage5-live/red-managed-sdk.log`.

1. **mb-pi crashed on Node 26 with `Cannot use import statement outside a module`.** The real agentDir `package.json` is `{"type":"commonjs"}`.
   - Fix: the ESM now installs as `bin/mb-pi.mjs`. `bin/mb-pi` is a POSIX sh launcher that follows symlinks.
   - Both files are owned and hashed. The foreign-file refusal covers both, and uninstall removes both.
   - The installer never touches Pi's own `bin/pi`.
   - Code: `adapters/_lib_pi_subagent.sh`, plus the manifest/refusal lines in `_lib_pi_extensions.sh`.
2. **Ordinary pi hit a tool conflict on `code_context` etc.** A project-level and the global `memory-bank-graph-rag.ts` registered the same tools.
   - Fix: a project copy (non-empty `PROJECT_ROOT`) returns without registering when `<agentDir>/extensions/memory-bank-graph-rag.ts` exists.
   - agentDir is `PI_CODING_AGENT_DIR`, else `~/.pi/agent`.
   - The check uses no runtime SDK import: a first version imported `getAgentDir` from the SDK, which broke 30 harness tests, so it was replaced.
   - This works in either install order. Stale project copies made by older versions need `pi.sh install` re-run in that project.
3. **mb-pi could not find the SDK under managed Pi 1.1.0.**
   - Fix: lookup order is `MB_PI_SDK_ROOT`, then `<agentDir>/install/current-version` → `releases/<v>/node_modules/@earendil-works/pi-coding-agent` (the version string is validated), then `pi` on PATH.
   - The launcher prepends `${XDG_DATA_HOME:-~/.local/share}/pi-node/current/bin`, as Pi's own launcher does.
4. **Tests no longer guess the SDK location.** `tests/pytest/conftest.py` resolves it once, using the real HOME: `MB_PI_SDK_ROOT`, then the managed layout, then `npm root -g`. It then sets `MB_PI_SDK_ROOT`, `PI_PACKAGE_ROOT` and `PI_SDK_ROOT`.
