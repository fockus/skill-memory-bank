# Генерация спек обязана прогонять артефакты через реальных потребителей

8/8 спек группы sdd-vision-pipeline прошли `mb-spec-validate.sh` и собрали 96 находок ревью
(Codex gpt-5.6-sol, 8 агентов): `Role: mb-*` → парсер даёт `mb-mb-*` (44 задачи), 39 сценариев
без `<!-- mb-scenario:N -->`-маркеров (валидатор no-op), 2 фальшиво-красных эвала, ~12 word-grep
эвалов, кириллические имена сценариев → вырожденные `test_id`.

**Why:** валидатор проверяет структуру (пол), не семантику; генератор писал форматы по памяти и
сам себя сертифицировал; ни один заявленный Eval не исполнялся при генерации.

**How to apply:** после генерации спеки — обязательная батарея (`commands/sdd.md` § Generation
self-check): spec-validate → scenario-extract паритет (+ASCII-имена) → mb_work_items.py
(bare Role, агент существует) → исполнение каждого Eval с ожиданием red → сверка межспековых
контрактов с обеих сторон. Кодовые гейты — svp-sdd-core REQ-015/C8. Форматы копировать из
`references/templates.md` и зелёной спеки, не из памяти.
