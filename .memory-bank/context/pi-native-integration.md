Approved by Anton on 2026-10-05: «да. согласен» (AGR-055), provider inheritance correction (AGR-056), and «подключим Tintin и сразу же адаптируем меморибанк и под него тоже, как ты описал выше» (AGR-057). ## Goal

Make the explicitly opted-in Pi installation execute Memory Bank natively: native command handlers, automatic project-local session capture and restoration, compaction handoff, usable vector code search, native graph tools and graph lifecycle hooks, and named role execution with the selected project's existing pipeline gates.

## Architecture

A thin native Pi adapter reuses portable MB scripts for bank resolution, planning, state, verification, severity/approval gates, handoff and graph operations. A single MB command/pipeline surface selects either nicobailon/pi-subagents or @tintinweb/pi-subagents through public integration APIs. Backend modules normalize launch, completion, cancellation and supported continuation contracts; they do not implement another agent executor. Core MB gates remain independent of backend-specific acceptance features. Native mechanics execute code. Agentic planning/analysis invokes the existing command/role instructions explicitly; a markdown router alone is not acceptance of native /mb work.

Split responsibilities into command routing, subagent bridge/pipeline driver, session lifecycle, graph hooks and installation. Keep old non-Pi behavior and opt-in defaults intact. Resolve the bank from live ctx.cwd with scripts/_lib.sh (including registered global and legacy banks), never the installation directory. Global templates bake PROJECT_ROOT as an empty string. Runtime captures and callbacks belong to a session identity; reload and project switches dispose/reset them.

## Opt-in managed startup and host binding — AGR-058

Provide an adapter-owned entrypoint at `<Pi agentDir>/bin/mb-pi`, installed explicitly in Stage 5. It composes the existing public Pi SDK `DefaultResourceLoader`, event bus, session/runtime and `InteractiveMode`; it does not replace the `pi` executable, build another TUI, loop over model calls itself or execute children. Nico/Tintin public services remain the only child executors. The managed path is optional; ordinary Pi and unrelated settings/resources remain unchanged. Do not add global auto-loading of Tintin or alter PATH/aliases as a shortcut: load the requested package in the explicitly managed composition unless the owner separately authorizes ordinary-session activation.

The composition root owns the loader and exact component/factory provenance. It produces a live, non-model-supplied binding containing the session ID, runtime generation, authoritative loaded-component inventory and effective settings captured from the specific Tintin factory instance. The binding is not inferred from tool names, missing replies, raw JSON parameters, filesystem settings alone or a stale singleton. Invalidate it on runtime/session replacement, relevant settings reload, startup failure and disposal. Restore subscriptions against the new generation; late callbacks cannot publish into it. Unknown/mismatched/invalidated binding refuses managed child dispatch, while deterministic context/start and ordinary unmodified Pi remain usable.

Use normal SDK discovery and explicit owner-owned overlays; preserve providers/credentials, active model selection, project trust, supported builtin tools, skills/prompts and unrelated customizations. Load each backend/MB service once. If a customization cannot be safely composed, diagnose it before the first model/child call rather than deleting, disabling or silently replacing it. Tintin automatic mentions must be authoritatively disabled in the managed instance; an enabled/unknown actual setting blocks startup/managed dispatch. A runtime-local overlay may override this one setting without writing a foreign config, but only if the public factory demonstrably honors it. Unsupported isolation or auto-commit behavior refuses before launch; no worktree downgrade or commits.

Stage 1 owns the minimal binding producer/consumer and bootstrap core in `adapters/pi_native_host.mjs` and `adapters/pi_native_bootstrap.mjs`, with test-first behavioral contracts and a real, model-free SDK smoke in sandbox HOME. A fake injected binding only tests the consumer. Acceptance of producer feasibility requires actual public loader/factory/session objects, precise attribution, coexistence and lifecycle invalidation evidence without model/child execution. Stage 5 adds installed entrypoint packaging, ownership/removal/rollback, actual TUI launch and live backend/model/whole-plan acceptance. New libraries, private Pi/engine imports and another execution transport remain prohibited.

## Explicit backend contract

Tintin is the default (AGR-088/ADR-013, 2026-10-08; Nico has no public child-session inventory). Nico stays opt-in under `registerSubagentCapabilityCeiling`, its runtime inventory reported UNVERIFIED. `/mb work <target> --backend nico|tintin` is a run-specific selection; a bank may opt in with `pi_subagent_backend=nico|tintin` in `.mb-config`. The run flag wins for a new run; absence means the bank setting, then Nico. An invalid selection, unavailable selected service or incompatible role/capability fails before launching any step. Resume retains its recorded backend and refuses a conflicting request. Persist backend, parent session/source identity and backend-native child ID together; status/cancel/continuation never send an ID to the other service.

Do not register a second `/mb` or `mb_dispatch_subagent`. The parent model must not choose between raw executor tools for MB work. Child profiles expose only the selected backend's permitted tools; ordinary leaves cannot delegate. Prevent the unselected backend's delegation tools and automatic agent-mention path from bypassing the chosen MB route in managed sessions. Do not claim that hiding tools disables arbitrary extension factory side effects or creates an OS sandbox. Existing non-MB host customizations must remain intact; any incompatible configured surface is diagnosed explicitly rather than silently overwritten.

Provider/model inheritance is validated against the effective child configuration, not only the requested RPC fields. For Tintin, account for authoritative frontmatter, fuzzy/provider fallback, default general-purpose fallback, differing RPC option spellings and shared agent discovery paths. Reuse composed MB role prompts through adapter-owned profiles without overwriting foreign agent definitions. Unknown/disabled roles, provider drift, missing mandatory tools and a dropped worktree request fail closed. Preserve the original mandatory gate order and verdict checks for both backends. A configured external runner must not be substituted with a native general-purpose agent; an unsupported runner/control capability is an explicit preflight blocker, not permission to weaken the pipeline. Backend-specific extra capabilities are advertised separately; no blanket parity claim.

Nico uses `subagents:rpc:v1:*`; Tintin uses `subagents:rpc:*` and top-level lifecycle events. Unique correlation IDs, exact ownership, listeners registered before spawn, result consumption and bounded teardown are required. Tintin's documented RPC does not expose every Agent-tool operation; use only its documented public bus/registry contracts, never private manager imports or forged internal fields. Durable MB continuation from confirmed steps must not be confused with resuming an individual child conversation. Escalate a missing mandatory public capability to the parent rather than inventing support.

### Alternatives and decision

Installing two raw tool surfaces and asking the model to prefer one is rejected: it leaves execution and fallback ambiguous. Replacing Nico outright is rejected: it discards the current evidence and working integration direction. The approved choice is two thin adapters with one selected backend per run, one MB state/gate layer and a common contract test battery. Unsupported optional operations remain explicit capability errors.

## Memory

Capture actual user input, completed turns/tools, touched files and outcomes in the existing session v2 schema. Idempotent start/resume/reload does not append another frontmatter header or reset turn counts. Restore bounded recent summaries and handoff into the next model context without replaying old text as a user request. Save a real handoff before compaction and restore it afterward. Finalization is awaited and bounded, summary policy is inherited rather than silently invoking a second CLI/provider. If an LLM summary is unavailable, retain usable deterministic session evidence and report its mode honestly. No memory crosses banks; a missing bank never gets silently initialized.

## Graph and vector search

Wrap existing graph/code-context/search scripts as native tools with timeout, cancellation and explicit error/degradation results. Lifecycle runs existing catchup/nudge mechanisms where compatible, without claiming the local wiki graph indexes the whole product Arcadia tree. Diagnose the observed FastEmbed cache validation failure before changing caching. Cache model files persistently outside OS temp directories, honoring existing overrides; a cold query must not encode a full corpus in the foreground. No new libraries. BM25 is a clearly identified fallback; acceptance of vectors needs actual local embedding inference after process restart with downloads disabled. Expensive wiki/extra optional features remain opt-in.

## Work and commands

Register /mb and MB aliases with real handlers. Preserve unrelated native commands, specifically /goal (MB goal lives at /mb goal). Mechanical commands invoke their portable scripts directly using argv, not interpolated shell strings. Work resolves the effective named pipeline with mb-pipeline.sh and mb-workflow.sh; target/range comes from mb-work-resolve.sh and mb-work-plan.sh. Thread source_path/source_topic/item_no to durable work state, respect resume/cycle/budget/protected paths and configured verify/review/judge/fix/done steps. AGR-056: default role execution inherits the orchestrator's provider and current model. Legacy family aliases such as opus/sonnet must not implicitly select another provider. Provider-qualified cross-provider overrides need explicit run-specific owner authorization; unresolved/conflicting aliases are not silently translated to another provider. Independent roles use separate fresh sessions, not necessarily different providers. Native execution must stop on an infrastructure failure, negative gate, corrupt verdict or cycle exhaustion; it must not silently fall back inline/CLI, substitute models, or mark checkboxes early. Reviewers use fresh context and return durable bound artifacts. Cancellation and errors preserve partial evidence.

## Safety and installation

Tool hooks reuse existing dangerous-command/protected-path guards, graph hints and applicable post-write synchronization. Nonblocking hooks fail open with bounded diagnostics; explicit safety guards fail closed as specified by their scripts. Do not represent a tool guard as an OS sandbox. Install via the existing explicitly requested Pi opt-in surface, including the separate AGR-058 managed entrypoint; verify idempotency, rollback and removal of only unchanged owned files. The managed entrypoint must not overwrite an existing user file, replace ordinary pi, auto-enable Tintin in ordinary sessions, or rewrite foreign configuration. Preserve preexisting settings, roles, prompts and foreign working-tree modifications; store preimages and hashes. Tests use sandboxed HOME. AGR-057 authorizes installation/probes of the requested Tintin package and its required dependencies, first in isolated test storage; no other new libraries or optional downloads. Candidate metadata on 2026-10-05: @tintinweb/pi-subagents 0.19.0, Pi peer dependencies >=0.84.0; the existing host is 1.0.2. Source/API inspection and fixture tests do not prove host compatibility. Real-host installation, additive settings, owned-file preimages and activation are parent-owned after Stage 5 candidate gates. Do not reload the current host while the original workflow owns live children. No commits, pushes or destructive git operations.

## Acceptance

A real installed Pi runtime must show handlers, tools and roles; execute native start and a bounded work fixture; write capture; restore that capture in a second session; save/restore compaction handoff; execute vector search offline after restart; exercise graph catchup/nudge; and refuse a negative verifier/reviewer/judge case without closing the work item. The same positive and negative governed contracts run against both backends, including when both are installed: exactly one selected executor, actual parent provider/model, unknown-role refusal, no cross-backend fallback, wrong-engine control rejection, cancellation and retained checkpoint identity. Memory/graph components remain single shared services, not one copy per backend. Mock/fixture event tests prove contracts, not live-runtime parity. Model-free SDK producer smoke is an intermediate integration gate, not proof of live TUI/provider/child execution; the installed managed entrypoint must still pass those Stage 5 checks. Ordinary-startup managed-work refusal must explain the explicit opt-in entrypoint, not launch it as a fallback. Record unsupported host APIs and blockers explicitly. Full planned completion requires all five updated implementation stages and final independent verification/review/judge, not installation alone. Additional Stage 1 backend behavior requires new observed RED/GREEN receipts; the earlier Nico-only receipts remain historical evidence and are not rewritten.
